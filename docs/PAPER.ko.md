# MAIOS: 기억·회상·거버넌스를 갖춘 임무 중심 인지형 AI 운영체제의 설계와 실증

**(연구논문 초고 v1 — 2026-07-10)**

저자: 권영환 (소속·표기 방식 추후 확정)
공동 설계·구현: Claude (Anthropic) — 대화형 공동개발, 기여 표기 방식 추후 확정

---

## 초록

대화형 AI의 능력이 급성장했음에도 그 사용 형태는 여전히 세션 단위의
휘발적 문답에 머물러 있다. 본 논문은 AI를 "질문에 답하는 도구"가 아니라
"임무를 중심으로 운용되는 체계"로 재구성한 로컬 AI 운영체제 MAIOS(MUSA
AI Operating System)의 설계와 구현, 그리고 실사용 코퍼스 기반 실증 결과를
보고한다. MAIOS는 (1) 관찰-이해-계획-행동-성찰-학습의 6단계 인지 루프,
(2) 지식그래프·수행일지·산출물로 구성되어 실행 간 지속되는 워크스페이스
기억, (3) 새 목표 수행 시 과거 경험과 문서를 자동 회수해 프롬프트에
주입하는 기억 회상, (4) 고위험 목표를 차단하고 인간 승인을 요구하는
거버넌스 게이트를 통합한다. 모든 LLM 의존 단계는 프로바이더 부재 시
결정론적 휴리스틱으로 대체되는 폴백 설계를 따르며, 이로써 전체 시스템이
API 접근 없이 시험 가능하다(테스트 480개, 분기 커버리지 95.9%). 실제
저술 코퍼스(33개 파일, 728KB)를 이용한 실증에서 단위 시험이 포착하지
못한 세 가지 규모 결함 — 삽입당 전체 영속화와 이차적 자동 연결의 결합,
수행 기록이 자기 자신을 재섭취하는 되먹임 팽창(단일 노드 6.7MB 도달),
토큰화기의 한글 불가시성 — 을 발견·수정하였고, 수정 후 대량 흡수는 1초
미만, 반복 질의는 약 1.2초에 안정화되었다. 본 연구는 개인 지식노동의
맥락에서 "기억하는 AI 체계"가 부딪히는 실제 공학 문제와 그 해법을
구체적 수치와 함께 제시한다는 점에서 기여를 갖는다.

**주제어**: AI 에이전트, 인지 아키텍처, 장기 기억, 검색 증강, AI 거버넌스,
임무형 지휘

## 1. 서론

### 1.1 문제 제기

대규모 언어모델(LLM)은 요약·작문·분석에서 실용 수준에 도달했으나,
일반 사용자가 이를 활용하는 지배적 형태는 여전히 채팅이다. 채팅 패러다임은
세 가지 구조적 한계를 갖는다. 첫째, **휘발성** — 세션이 끝나면 맥락과
교훈이 소실되어, 사용자는 매번 배경을 다시 설명한다. 둘째, **수동성** —
모델은 묻는 말에 답할 뿐, 큰 목표를 분해하고 순차 수행하며 중간 산출을
잇는 운용 구조가 없다. 셋째, **통제 부재** — 자율성을 높인 에이전트
프레임워크들은 반대로 인간의 승인 개입 지점을 체계화하지 못했다.

본 연구는 이 세 한계를 "AI를 운영체제처럼 운용한다"는 관점에서 통합적으로
다룬다. 운영체제가 프로세스·메모리·권한을 관리하듯, MAIOS는 목표(임무)·
기억·권한을 관리한다.

### 1.2 연구 질문

- RQ1. 세션을 넘어 지속·회상되는 기억 체계는 개인용 로컬 환경에서 어떤
  아키텍처로 실현 가능한가?
- RQ2. LLM 의존 기능과 오프라인 검증 가능성은 양립할 수 있는가?
- RQ3. 그러한 체계가 실제 사용 규모(수백 문서 청크, 반복 질의)에
  노출될 때 어떤 결함이 드러나며, 어떻게 해소되는가?

### 1.3 기여

1. 인지 루프·영속 기억·회상·거버넌스를 단일 체계로 통합한 공개 구현체
   (GitHub, MIT 라이선스, 테스트 480개·커버리지 95.9%).
2. 모든 LLM 단계가 휴리스틱으로 대체되는 **폴백 설계 원칙**의 정식화 —
   API 없는 완전 오프라인 시험 가능성.
3. 실사용 코퍼스 실증에서 발견한 세 가지 규모 결함의 사례 분석과
   정량적 수정 효과(6절) — 특히 **자기 기록 되먹임 팽창**은 기억을 가진
   에이전트 일반에 적용되는 위험으로, 본 연구가 명명·분석한다.
4. 한글 교착어 특성을 반영한 무의존성(zero-dependency) 검색 개선 —
   음절 바이그램 + TF-IDF.

## 2. 관련 연구

**에이전트 프레임워크.** AutoGPT, LangChain, AutoGen, CrewAI 등은 LLM의
도구 사용과 다중 에이전트 협업을 구조화했다. 그러나 이들의 기억은 주로
세션 내 컨텍스트 또는 외부 벡터 저장소 연동에 머물며, 수행 이력으로부터의
교훈 추출·재주입, 그리고 인간 승인 게이트를 1급 개념으로 통합한 경우는
드물다. MAIOS는 프레임워크(라이브러리)가 아니라 운영체제(상주 체계)의
은유를 취해, 기억·회상·거버넌스를 기본 동작으로 내장한다.

**메모리 증강 에이전트.** MemGPT 계열 연구는 LLM 컨텍스트를 가상 메모리로
확장하는 관리 기법을 제안했다. MAIOS의 워크스페이스는 이와 상보적으로,
모델 외부의 구조화된 장기 기억(지식그래프·일지)을 두고 회상 시점에만
발췌를 프롬프트에 주입한다. 이는 모델 교체(model-agnostic)에 강건하다.

**인지 아키텍처.** SOAR, ACT-R, BDI 등 고전 인지 아키텍처는 지각-결정-
행동 순환과 장기/작업 기억의 분리를 정식화했다. MAIOS의 6단계 루프는
이 전통의 경량 실용화로 볼 수 있으며, 차이는 각 단계가 LLM 호출로
증강되되 호출 실패 시 결정론적으로 퇴행한다는 점이다.

**임무형 지휘와 인간 통제.** 군사 지휘 이론의 임무형 지휘(Auftragstaktik)는
"의도를 공유하고 실행을 위임하되, 한계를 명시"하는 통제 양식이다. MAIOS의
거버넌스 게이트(위험 분류, 금지어, 인간 승인)는 이 원리의 소프트웨어적
번역으로, 자율 에이전트에 대한 인간 통제 지점을 실행 전 단계에 정형화한다.

## 3. 설계 원칙

MAIOS는 여섯 원칙을 따른다(프로젝트 비전 문서에서 정식화).

| 원칙 | 구현상의 귀결 |
|---|---|
| P1. 임무 중심(Mission Driven) | 모든 동작의 단위는 "목표"이며 수행 기록이 1급 객체다 |
| P2. 모델 불가지(Model Agnostic) | 프로바이더 추상화(BaseLLMProvider), mock/OpenAI/Claude/Gemini 교체 가능 |
| P3. 지식 중심(Knowledge Centric) | 산출물·경험·문서가 모두 지식그래프에 축적된다 |
| P4. 품질 우선(Quality First) | 정적검사 3종 + 분기 커버리지 95% 강제 CI |
| P5. 장기 지속(Long-term Continuity) | 워크스페이스 영속화, 재실행 간 복원 |
| P6. 인간 지휘·AI 실행(Human Command, AI Execution) | 거버넌스 게이트, 고위험 인간 승인 |

여기에 구현 과정에서 일곱째 원칙이 추가되었다:

**P7. 폴백 설계(Graceful Degradation)** — LLM을 요구하는 모든 단계
(이해·실행·성찰·분해·종합)는 프로바이더 부재 또는 호출 실패 시
결정론적 휴리스틱으로 대체된다. 이 원칙의 실익은 두 가지다.
(a) 전체 파이프라인이 API 키 없이 시험 가능해져 CI가 외부 의존을 갖지
않는다. (b) 운용 중 프로바이더 장애가 체계 정지가 아니라 품질 저하로
나타난다. 실제로 본 연구의 개발 기간 중 API 크레딧이 전무한 상태에서
480개 테스트 전부와 실코퍼스 실증이 수행되었다.

## 4. 아키텍처

### 4.1 전체 구조

```text
사용자 목표 (CLI: pursue/project/research/ingest/shell)
  → Workspace          영속 기억: 지식그래프, 기억저장소, 일지, 산출물
  → AGIFoundation      거버넌스 게이트, 목표 등록, 진화 보고
  → CognitiveLoop      6단계 인지 사이클
       관찰(Observe)     런타임 상태로 세계모델 갱신
       이해(Understand)  세계 컨텍스트 구성 + 기억 회상(MemoryRecall)
                         + 선택적 LLM 상황 해석
       계획(Plan)        ExecutiveBrain의 플래너 선택·결정
       행동(Act)         TaskExecutor(LLM 산출) / 연구 엔진 / 기타 플래너
       성찰(Reflect)     ImprovementReport 생성(선택적 LLM 성찰)
       학습(Learn)       세계 전이 기록, 교훈 추출, 경험 노드 축적
  → GoalPursuit / ProjectPursuit 기록 + artifacts/<id>.md
```

계층 명칭에 관한 주의: 최상위 통합 계층의 클래스명 AGIFoundation은
아키텍처상 위치를 가리키는 이름일 뿐이며, 본 체계는 범용 인공지능이
아니라 자율 워크플로우 오케스트레이션 계층이다. 공개 문서에도 동일한
한정을 명시하였다.

### 4.2 기억과 회상

워크스페이스는 네 저장소로 구성된다: 지식그래프(노드=문서 청크·경험·
성찰·개념, 간선=유사·도출 관계), 장기 기억 저장소, 목표 수행 일지,
프로젝트 일지. 회상(MemoryRecall)은 이해 단계에서 목표 문장으로
지식그래프를 검색해 내용성 노드(문서·개념·근거·경험·성찰)만 상위 k개
회수하고, 이를 (a) LLM 상황 해석 프롬프트와 (b) 실행 프롬프트에
"관련 기억" 블록으로 주입한다. 직전 수행들의 교훈 최근 5건도 별도
블록으로 주입되어, 세션과 프로세스를 넘는 행동 개선이 일어난다.

### 4.3 검색: 한글 친화 TF-IDF

초기 구현의 토큰화기는 `[a-zA-Z0-9_]+` 패턴만 사용해 **한글 텍스트가
검색에 전혀 보이지 않는** 결함이 있었다(6.3절). 개선된 검색은
(i) ASCII 단어 + 한글 음절 바이그램 토큰화("전쟁과"→{전쟁, 쟁과} —
교착어의 조사 결합에 강건), (ii) 역문헌빈도(IDF) 가중으로 희귀어 우대,
(iii) 용어빈도(TF) 로그 가중으로 주제 집중 문서 우대, (iv) 노드별 토큰
캐시로 반복 질의 비용 상수화를 결합한다. 외부 의존성과 사전 없이
구현되어 P2·P7과 정합한다.

### 4.4 거버넌스

모든 목표는 실행 전 정책 엔진 심사를 받는다: 금지어 검사(BLOCKED),
위험 분류(키워드 기반 LOW/MEDIUM/HIGH), 고위험 시 인간 승인 요구
(PENDING_APPROVAL). 승인은 명시적 행위(`--approve`, 셸 `/approve`)로만
부여되며 모든 판정이 감사 로그에 남는다. 프로젝트 수행 시 상위 목표와
하위 목표가 각각 심사된다.

## 5. 구현과 검증 방법론

### 5.1 대화형 공동개발

본 시스템의 v1.1 이후 전 기능은 인간 연구자와 LLM 기반 코딩
에이전트(Claude)의 대화형 공동개발로 구현되었다. 스프린트 단위(설계 제안
→ 인간 승인 → 구현 → 검증 → 1커밋)로 진행했으며, 설계 대안 제시와
우선순위 판단은 에이전트가, 방향 결정과 위험 수용은 인간이 담당했다.
이 개발 양식 자체가 P6(인간 지휘·AI 실행)의 재귀적 실천이라는 점을
부기한다.

### 5.2 품질 게이트

모든 커밋은 black(포맷), ruff(린트), mypy(타입), pytest(분기 커버리지
95% 강제)를 통과해야 하며 GitHub Actions CI가 Python 3.11/3.12에서
동일 게이트를 재검한다. v1.3.0 기준 테스트 480개, 커버리지 95.9%,
신규 모듈(인지 계층 전체)은 문장 기준 100%다. P7(폴백 설계) 덕분에
이 모든 검증은 네트워크 접근 없이 수행된다. LLM 경로 자체는 스크립트드
프로바이더(응답 대본 주입)로 시험하며, 실모델 종단 검증용 하네스
(`scripts/validate_live.py`)를 별도로 제공한다.

## 6. 실증 평가: 실사용 코퍼스 사례연구

단위 시험이 모두 통과한 상태에서, 저자 본인의 실제 저술 코퍼스
(단행본 원고 폴더: 33개 파일, 728KB, 한국어 위주)를 흡수·질의하는
실증을 수행했다. 그 결과 시험이 포착하지 못한 세 가지 규모 결함이
드러났다. 각 결함과 수정, 정량 효과는 다음과 같다.

### 6.1 결함 A: 삽입당 영속화 × 이차적 자동 연결

지식그래프는 노드 추가마다 전체 JSON을 재기록하고, 신규 노드를 기존
전 노드와 유사도 비교해 자동 연결했다. 대량 흡수에서 이는 시간 O(n²)·
저장 O(n²)로 복합되어, 실측 20초 동안 69개 노드에 간선 2,258개가
생성되며 사실상 정지했다. **수정**: 대량 삽입 구간의 영속화를 지연하고
종료 시 1회 기록하는 벌크 컨텍스트, 흡수 노드의 자동 연결 비활성화.
**효과**: 33파일 389청크 흡수 0.9초.

### 6.2 결함 B: 자기 기록 되먹임 팽창 (self-record feedback inflation)

수행 결과(연구 보고서 전문 포함)가 세계모델 전이와 경험 노드에 원문
그대로 내장되고, 다음 수행의 회상·연구가 그 거대 기록을 다시 소스로
회수해 재내장하는 순환이 발생했다. 실측에서 두 번의 반복 질의만에 단일
전이 노드가 6.7MB, 그래프 파일이 12.7MB에 도달했고 반복 질의는 2분을
초과했다(사실상 발산). 이는 **수행 기록을 기억에 남기는 에이전트 일반이
공유하는 위험**으로, 기록이 검색 대상이 되는 순간 기록 자체가 지수적으로
자기 증식할 수 있다. **수정**: (i) 기록 저장 시 결과 요약본만 내장
(상태·플래너·오류/산출 300자), (ii) 그래프 노드 내용 상한(8,000자),
(iii) 연구 소스 랭킹에서 내용성 노드(문서·개념·근거)를 자기 활동
기록보다 우선. **효과**: 동일 반복 질의 1.2초, 그래프 888KB 안정,
반복 질의가 자기 로그 대신 문서를 인용.

### 6.3 결함 C: 토큰화기의 한글 불가시성

검색 토큰화가 ASCII 패턴만 추출해, 한국어 질의는 문서 내 우연한 영단어·
숫자로만 매칭되고 있었다. 한국어 중심 코퍼스에서 검색 품질이 낮았던
근본 원인이며, 단위 시험이 영어 위주로 작성되어 은폐되었다. **수정**:
4.3절의 바이그램 + TF-IDF. **효과**: 통제 코퍼스에서 주제 일치 문서가
1위로 랭크되고("우크라이나 전쟁의 드론 교훈"→해당 문서), 장문서 간
점수 포화 동점(전원 1.25)이 차등(3.73/3.55/3.45)으로 해소되었다.

### 6.4 함의

세 결함의 공통점은 **작은 규모의 통제된 시험에서는 원리적으로 보이지
않는다**는 것이다(A: n이 작으면 저렴, B: 1회 수행에는 순환 없음,
C: 영어 시험 데이터에선 정상). 기억을 가진 에이전트의 검증에는 단위
시험·커버리지와 별도로 (i) 실데이터 규모 실증, (ii) 반복 사용(자기
기록 재노출) 실증이 필요함을 시사한다.

## 7. 한계와 향후 과제

- **실모델 미검증**: 본고 시점까지 전 기능은 mock/스크립트드 프로바이더로
  검증되었고, 실LLM 종단 검증은 하네스만 준비된 상태다. 분해 프롬프트의
  실모델 출력 적합성 등은 실검증 후 보고할 것이다.
- **검색의 어휘 한계**: 바이그램 TF-IDF는 표층 매칭이다. 의미 검색
  (임베딩)은 P2·P7을 유지하는 선택적 증강으로 설계 예정이다.
- **단일 사용자·단일 머신**: 워크스페이스는 동시 쓰기에 안전하지 않다.
- **거버넌스의 표층성**: 위험 분류가 키워드 기반이다. 의도 수준 분류는
  향후 과제다.
- **용어의 수사적 위험**: "인지", "자기 성찰" 등의 어휘는 기능적 은유이며,
  공개 문서 전반에 그 한정을 명시했다.

## 8. 결론

MAIOS는 휘발적 채팅을 넘어 기억·회상·거버넌스를 갖춘 임무 중심 AI
운용을 로컬 환경에서 구현했고, 실사용 코퍼스 실증으로 기억형 에이전트
특유의 규모 결함 세 가지를 식별·해소했다. 특히 자기 기록 되먹임 팽창은
수행 이력을 기억하는 모든 에이전트 설계가 점검해야 할 위험이라 판단한다.
전 구현·이력은 공개 저장소에서 재현 가능하다.
